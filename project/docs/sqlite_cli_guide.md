# Quick Guide: the `sqlite3` CLI

Oakhaven ships as a single SQLite database file, `project/oakhaven.db`,
generated by `python project/build.py`. This is a short reference for
poking at it from the command line.

## Opening the database

```bash
sqlite3 project/oakhaven.db
```

This drops you into an interactive `sqlite>` prompt. To run a single
command without entering the prompt:

```bash
sqlite3 project/oakhaven.db "SELECT COUNT(*) FROM bronze_sales;"
```

To run a `.sql` file (e.g. a lesson's exercise file) against the
database:

```bash
sqlite3 project/oakhaven.db < some_queries.sql
```

or, from inside the prompt:

```
sqlite> .read some_queries.sql
```

## Essential dot-commands

Dot-commands are CLI-only — they are not SQL and don't take a
semicolon.

| Command | What it does |
|---|---|
| `.tables` | List all tables and views. |
| `.schema TABLE_NAME` | Show the `CREATE TABLE`/`CREATE VIEW` statement for one object. |
| `.schema` | Show every `CREATE` statement in the database. |
| `.headers on` | Show column names in query output (off by default!). |
| `.mode column` | Aligned column output — the most readable mode for interactive use. |
| `.mode box` | Unicode box-drawing table output (nice for demos). |
| `.mode csv` | CSV output — useful for `.output` to a file. |
| `.width 10 20 10` | Fix column widths in `.mode column` (auto-sizing can be slow/wrong on wide text). |
| `.output somefile.csv` | Redirect all query output to a file. `.output stdout` to go back to the terminal. |
| `.quit` or `.exit` | Leave the CLI. |
| `.help` | List every dot-command. |

A good habit for interactive sessions:

```
sqlite> .headers on
sqlite> .mode column
```

## Common gotchas

- **No headers/columns by default.** A bare `sqlite3 file.db "SELECT
  * FROM t LIMIT 5;"` prints pipe-delimited values with no column
  names. Add `.headers on` and `.mode column` (or pass `-header
  -column` as CLI flags) if you want readable output.
- **Views vs. tables look the same in `.tables`.** All of
  `silver_*`, `dim_*`, `fact_*`, and `agg_*` in this project are
  `CREATE VIEW`, not tables — they compute their result at query time
  from the bronze tables underneath. `.schema silver_sales` will show
  you `CREATE VIEW`, not `CREATE TABLE`.
- **SQLite is dynamically typed.** A column declared `INTEGER` can
  still hold text if something inserts text into it (this is exactly
  why bronze columns like `order_total TEXT` or `discount_pct REAL`
  can contain "dirty" values like `"TBD"` or `15` instead of `0.15` —
  SQLite won't stop you). Don't assume a column's declared type
  matches every value in it in the bronze layer.
- **String comparisons are case-sensitive by default**, except
  `LIKE`, which is case-insensitive for ASCII. `WHERE state = 'ca'`
  will *not* match `'CA'`; `WHERE state LIKE 'ca'` will.
- **No `TRUE`/`FALSE` literals in older SQLite; use 1/0.** Modern
  SQLite (3.23+) does accept `TRUE`/`FALSE` as aliases for 1/0, but
  this project's boolean-ish columns (`is_active`, `is_manager`,
  `is_discontinued`) are cleaned to real 0/1 integers in the silver
  layer specifically so you don't have to think about this.
- **Rerunning the build deletes the file.** `python project/build.py`
  removes `oakhaven.db` and recreates it from scratch every time —
  don't leave an open `sqlite3` session pointed at it across a
  rebuild, or your session may see a stale/locked file. Reconnect
  (`sqlite3 project/oakhaven.db`) after rebuilding.
- **Recursive CTE row limits.** `bronze_calendar` is built with a
  `WITH RECURSIVE` statement (`project/bronze/calendar_recursive_cte.sql`).
  Stock `sqlite3` has no special row-count limit on recursive CTEs
  beyond memory, but if you write your own recursive query and forget
  the `WHERE` bound on the recursive term, it will run until it
  exhausts memory or you hit Ctrl-C.

## Inspecting a view's definition

Since the silver/gold layer is entirely views, the fastest way to
understand what a column actually means is to read its SQL:

```
sqlite> .schema silver_sales
```

or just open the corresponding file directly — `project/silver/silver_sales.sql`,
`project/gold/fact_sales.sql`, etc. — they're the ground truth.
