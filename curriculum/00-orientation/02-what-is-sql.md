## The idea

SQL is a language for talking to a database. Like any language, it has
a vocabulary and grammar, but it's a small one — a working SQL
vocabulary is a few dozen keywords, not thousands. What makes it feel
big at first is that those few keywords combine in a lot of ways.

The good news: this entire course is organized so you learn one piece
of that vocabulary at a time, always against the same real database,
so nothing you learn is abstract for long.

## Three flavors of SQL statement

SQL statements are usually grouped into a few families, based on what
they *do* to the database:

**DDL — Data Definition Language.** Statements that define or change
the *structure* of the database: creating tables, adding columns,
setting up constraints. Keywords: `CREATE`, `ALTER`, `DROP`. You'll see
this later, when we look at how Oakhaven's tables were built and how
views are defined — but you won't be writing much DDL yourself early
on.

**DML — Data Manipulation Language.** Statements that change the
*data inside* tables: adding, updating, or deleting rows. Keywords:
`INSERT`, `UPDATE`, `DELETE`. In this course, Oakhaven's database file
is shared and treated as read-only — you'll learn to *recognize* DML
when you see it, but you won't be running it against the practice
database.

**DQL — Data Query Language.** Statements that *ask questions* of
existing data without changing anything. There's really one keyword
that matters here: `SELECT`. This is where you'll spend nearly all
your time.

Some people fold DQL into DML, since technically both matter, but
splitting it out is useful for a course like this: it tells you
upfront where the weight is. If you get comfortable with `SELECT`,
you can do the overwhelming majority of real-world SQL work — writing
reports, exploring data, answering business questions, building the
kind of analytics views you'll see in Oakhaven's "gold" layer later.

## Why we'll mostly write queries, not writes

This might feel like a strange thing to promise in a course that calls
itself "SQL practice" — that you'll barely touch `INSERT` or `UPDATE`
— but it reflects how SQL actually gets used day to day by analysts,
data scientists, and most engineers. The data usually already exists,
generated by some application or import process (in Oakhaven's case,
by a build script that manufactures a realistic, deliberately messy
dataset once). Your job is to *ask good questions of it*: filter it,
sort it, summarize it, clean it up, join it together, and shape it
into something useful.

That's `SELECT`. Everything from Tier 1 onward builds outward from
that single keyword.

## Key takeaways

- SQL statements fall into three rough families: **DDL** (structure),
  **DML** (writing data), **DQL** (reading data).
- This course focuses almost entirely on **DQL** — `SELECT` — because
  that's where the vast majority of real SQL work happens.
- You'll query the same database, Oakhaven, throughout the whole
  course, treating it as read-only.
