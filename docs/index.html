sql-practice

A portable, self-generated path from your first SELECT to dimensional modeling — built around a small, realistic retail database you build yourself with one command.

What this is

sql-practice is a SQL curriculum you run entirely on your own machine. There's no server, no account, and no sample dataset to download — instead you generate Oakhaven, a fictional outdoor-gear retailer's database, with a single Python script powered by Faker and SQLite.

Oakhaven is built as a small medallion architecture: a messy bronze layer (real-world data quality problems — inconsistent casing, null foreign keys, malformed numbers), a cleaned silver layer, and a modeled gold layer of star-schema dimension and fact tables plus pre-aggregated views. You write the SQL that moves data through every one of those layers yourself, over the course of the curriculum.

Because the generator uses a fixed random seed, every learner's copy of oakhaven.db is byte-identical — the same 600 customers, 150 products, 35 employees, and 12,000 sales line items, every time it's built, on every machine.

About the Oakhaven database

Oakhaven is a fictional outdoor-gear retailer. Its database is generated locally by project/build.py and is not committed to the repository — you build it yourself, and because the generator is seeded, your copy will match everyone else's exactly.

  • 600 customers, 150 products, 35 employees, and 12,000 sales line items (7,199 distinct orders) across a bronze → silver → gold pipeline
  • A date dimension built with a recursive CTE spanning 2018-01-01 through 2038-12-31 (7,670 days) — no Python date loop, pure SQL
  • Deliberately messy bronze data: inconsistent casing and spacing in categories, departments, and regions; null and malformed values; orphaned foreign keys; a discount-percent unit bug — all fixed as you build the silver layer
  • A gold layer of star-schema dimensions (dim_customer, dim_product, dim_employee, dim_date), a fact table (fact_sales), and pre-built aggregate views
